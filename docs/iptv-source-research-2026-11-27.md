Все цифры качества ниже — заявленные метки в плейлистах, значения API или измерения самих проектов-источников. Они не подтверждают качество конкретного потока. Поток считается подтверждённым 1080p только после локального `ffprobe`, который вернул `height >= 1080`. До этого используется статус «кандидат, не измерено».

В отчёте нет потоковых URL, токенов, логинов и персональных данных. Ссылки ведут на страницы проектов, их документацию и публичные плейлисты. Публичный плейлист — это не отдельный поток: он содержит ссылки на потоки, которые требуют собственной проверки.

## Что выбрать для пилота

Базовый слой — DuckKota: 100% логотипов, 482 российских канала, 247 каналов с измеренным `best_quality=1080p` в API и MIT на код. Но отдельной группы «Региональные» у него нет, поэтому региональный слой нужно брать из уже подключённого Free-TV (22 строки Regional, 21 с потоком) или из GoodTV (156 «Региональные»). Free-TV не имеет лицензии, а GoodTV имеет только 13% логотипов и 37 каналов 18+, которые надо вырезать. Компромисс — Free-TV как источник региональных кандидатов, но с ручным подтверждением каждого потока и без публикации данных Free-TV как самостоятельного пакета.

Если лицензия является жёстким требованием, из основных кандидатов остаются DuckKota, iptv-org, chelslava и nexonic; GoodTV тоже MIT, но требует чистки 18+ и логотипов. Из них только DuckKota и nexonic дают измеренные 1080p-срезы, а chelslava ближе всего к Android TV/TiviMate по формату и уже исключает adult. iptv-org — самый чистый по лицензии и логотипам, но не даёт региональных групп и не измеряет качество.

Если региональные группы являются жёстким требованием, без Free-TV, GoodTV или tv-rus не обойтись. Тогда придётся принять один из компромиссов: отсутствие лицензии у Free-TV и tv-rus, слабые логотипы и 18+ у GoodTV, либо отсутствие лицензии и неясное происхождение у ngrch. Последний вариант не рекомендуется: в его README перечислены m3u.su, dmi3y-tv.online, loganettv, Dimonovich и Rafail1082, то есть смесь агрегаторов с неясными правами.

Минимальный пилот: DuckKota RU + региональные строки уже подключённого Free-TV + логотипы из iptv-org/database (Unlicense). Затем — дедупликация по нормализованному URL, исключение группы 18+, отдельный профиль kids с PIN, ffprobe-аудит и только после него публикация. Такой набор не требует передачи credentials и не включает платные списки.

Новые кандидаты не добавлены в `tools/iptv-sources.txt` именно потому, что этот пилот ещё не прогнан. Добавление URL без полного аудита нарушило бы правило «в плейлист только измеренные потоки ≥1080 строк».

## Как измерять ffprobe

Главное правило: 1080p — это не слово в названии канала, а измеренные `width` и `height` видеопотока. Пока ffprobe не вернул высоту, качество считается неизвестным. Метка `1080p` в M3U, `best_quality` в API и даже «Measured 1080p» в чужом плейлисте — это только кандидат на проверку.

В проекте уже есть штатный маршрут: `tools/iptv-check-auto.sh` вызывает `tools/iptv-merge.py` и `tools/iptv-verify.py`. `iptv-merge.py` извлекает разрешение из ограниченного буфера MPEG-TS через ffprobe, `iptv-verify.py` записывает `stream_height` в CSV и историю, а `tools/check-public-release.py` требует итоговую метку не ниже 1080p. Для разовой проверки одного потока используется такой вызов:

```bash
timeout 40 ffprobe -v error -hide_banner \
  -rw_timeout 15000000 -analyzeduration 10000000 -probesize 10000000 \
  -select_streams v:0 \
  -show_entries stream=codec_name,width,height,avg_frame_rate,bit_rate,pix_fmt \
  -show_entries format=format_name,bit_rate \
  -of json "$STREAM_URL"
```

`-rw_timeout` задаёт тайм-аут чтения в микросекундах, `-analyzeduration` и `-probesize` дают ffprobe достаточно данных для определения параметров. Для живого HLS не используйте `-count_frames`: поток бесконечный. Ограничьте чтение, например `-read_intervals "%+10"`, если нужно измерить 10 секунд.

Для HLS master-плейлиста одного ffprobe недостаточно: демуксер выбирает вариант по своим правилам, а не обязательно самый высокий. Сначала скачайте master и разберите `#EXT-X-STREAM-INF`:

```bash
curl -fsSL --compressed --max-time 20 "$STREAM_URL" \
  | grep -E '#EXT-X-STREAM-INF|^[^#]'
```

В строках `#EXT-X-STREAM-INF` ищите `RESOLUTION=1920x1080` и `BANDWIDTH=...`, затем проверяйте каждый вариант отдельно. Если master отдаёт 1080p, 720p и 576p, ffprobe нужно запускать по каждому URL варианта и брать максимальную измеренную высоту. Для DASH/MPD разбирайте `Representation height="..."` и проверяйте выбранный `BaseURL`.

Для YouTube, VK Video и OK.ru прямой ffprobe обычно не работает: это не HLS-поток, а страница или адаптивный манифест. Сначала разрешите поток через `yt-dlp -f best -g`, затем передайте полученный HLS URL в ffprobe. Такие записи нельзя считать обычными M3U-потоками, и их нужно маркировать отдельно.

Минимальная процедура приёмки:

1. Прогнать каждый поток 3 раза в разные часы, минимум из двух точек наблюдения: российский резидентный IP и зарубежный runner.
2. Успехом считать 2 из 3 запусков, где ffprobe вернул видео и высоту.
3. Записывать `width`, `height`, `codec_name`, `avg_frame_rate`, `bit_rate`, `format_name`, а также хеш URL, а не сам URL.
4. Классифицировать: `height >= 1080` — подтверждённый 1080p; `720 <= height < 1080` — HD; `height < 720` — SD; нет данных — unknown.
5. Проверять битрейт: 1080p с очень низким битрейтом может быть апскейлом; 1080p-метка не гарантирует качество картинки.
6. Не смешивать геоблокировку с поломкой: 403/451 из другой страны — это ограничение доступа, а не мёртвый поток.

Проверка метода, а не аудит всего плейлиста:

| Канал | Заявлено | Измерено ffprobe | Вывод |
|---|---|---|---|
| 1HD Music Television (iptv-org) | 1080p | 1920×1080, h264, 50 fps | совпало |
| 2x2 (iptv-org) | 576p | 720×576, h264, 25 fps | совпало |
| 3ABN Russia (iptv-org) | 720p | 1280×720, h264, 25 fps | совпало |
| 15+ Music (DuckKota) | 1080p | ошибка ввода-вывода | не подтверждено |

Эти четыре строки не заменяют полный аудит: они показывают, что методика различает 1080p, 720p и 576p, и что заявленная метка может не совпасть с фактом.

## Ограничения и правовые оговорки

Лицензия репозитория не равна праву на трансляцию. iptv-org, DuckKota, chelslava, nexonic и другие проекты хранят только ссылки на публичные потоки; права на каналы, логотипы и EPG остаются у вещателей. MIT, Unlicense или CC0 покрывают код, текст плейлиста или метаданные, но не дают Panadonik права на ретрансляцию чужих каналов. Это прямо оговорено в README iptv-org, DuckKota, chelslava и nexonic.

Публичный URL не равен разрешению на распространение. Даже если поток открывается без логина и токена, это не значит, что вещатель разрешил его публиковать в составе Panadonik. Для производства нужен реестр источников, ручное подтверждение каждого потока, атрибуция и процедура удаления по жалобе правообладателя. Nexonic в своей политике прямо требует доказательство официального бесплатного стрима для official-тира и отдельно маркирует community-потоки без такого доказательства.

Отсутствие лицензии — не юридический запрет, но и не разрешение. Free-TV и tv-rus не дают явной лицензии на переиспользование данных; их можно использовать как указатель на кандидаты, но не как готовый пакет для публикации. GoodTV и substanc имеют лицензию на репозиторий, однако качество и права конкретных потоков всё равно требуют проверки: у GoodTV есть группа 18+, у substanc — token-like URL и зеркала платных каналов.

Результаты этого отчёта — кандидаты, а не доказательство. Они не закрывают release gate, не подтверждают доступность с приставки и не заменяют проверку по первичным источникам. Перед добавлением в `tools/iptv-sources.txt` нужен полный локальный прогон, а перед публикацией — проверка на целевой приставке.
