# Проверки качества dev- и стабильных выпусков

Каждый GitHub Release должен включать автоматический отчёт тестов, сводку анализа журналов и протокол проверки на целевой приставке. Сырые журналы и полные IPTV URL в публичные артефакты не прикладываются.

## Автоматические проверки в CI

- `python3 -m unittest discover -s tests -v`: нормализация категорий, флаги регионов, порядок 18+, устранение дублей, маскирование секретов в отчёте журнала и критические настройки ADB/`su` в образе.
- Проверка синтаксиса shell/Python и JSON списка Obtainium.
- `tools/check-public-release.py`: отсутствие учётных данных в URL, минимум 20 каналов 18+ и категория 18+ на первом месте плейлиста.
- Полная сборка eMMC OTA, проверка структуры образов и подписи прежним ключом проекта.
- Архив чистой установки eMMC для Rockchip Loader со всеми регионами, `rkusb.py`, инструкцией и внешним SHA-256.
- `tools/analyze-release-logs.py`: подсчёт предупреждений и ошибок сборки; критические ошибки блокируют публикацию. Отчёт анализа прикладывается к Release.
- `tools/check-release-evidence.py`: проверка аппаратного протокола соответствующего тегу выпуска.

Тег `dev-v<версия>` запускает GitHub prerelease. Dev-путь не требует `security_review=pass`; текущие риски остаются видимыми в приложенном протоколе. Он по-прежнему требует успешных автотестов и функциональных/стабильностных проверок: холодного старта, журналов, QR, сети, IPTV, торрента, графики и отключённого дискового swap. Обычный тег `v<версия>` требует также закрытой проверки безопасности.

## Проверки на приставке

До публикации заполнить `docs/release-qa/<версия>.json`. Проверить холодную загрузку от подачи питания (не более 10 секунд), журналы после загрузки, QR-запуск VLC и Total Commander, проводную и Wi-Fi сеть, воспроизведение IPTV и торрента, плавность видео и графическую нагрузку. Проверить, что дисковый swap выключен. Стабильный выпуск требует также проверки безопасности и нулевого `untriaged_errors`; dev-выпуск может оставить security-review незакрытым, но не должен выпускаться с неразобранными ошибками, влияющими на стабильность или функции.

Сборочный GitHub runner не имеет доступа к живой приставке, поэтому его успешная сборка не считается результатом аппаратных проверок. Все автоматические и аппаратные отчёты публикуются вместе с OTA и APK. Пример незаполненного протокола для текущего 0.4.0 показывает, что именно ещё требуется проверить.
