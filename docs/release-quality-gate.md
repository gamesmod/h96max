# Проверки качества dev- и стабильных выпусков

Каждый GitHub Release должен включать автоматический отчёт тестов, сводку анализа журналов и протокол проверки на целевой приставке. Сырые журналы и полные IPTV URL в публичные артефакты не прикладываются.

## Автоматические проверки в CI

- `python3 -m unittest discover -s tests -v`: нормализация категорий, флаги регионов, порядок 18+, устранение дублей, маскирование секретов в отчёте журнала и критические настройки ADB/`su` в образе.
- Проверка синтаксиса shell/Python и JSON списка Obtainium.
- `tools/iptv-merge.py`: измеренное через `ffprobe` разрешение видеокадра из медиасегмента не ниже 1080 строк; HLS/URL/название без измеренного кадра не считаются доказательством. Также проверяются единые русские категории/флаги, 18+ первой, исключение детских потоков и дубли URL/названий с учётом времени/качества.
- `tools/iptv-verify.py`: журнал проверок JSONL без полных URL; доступность отдельно по областям `global`/`device`, рейтинг за 30 дней и исключение только после трёх отказов с интервалом не менее 24 часов. Разрешение ниже 1080 исключается по качеству сразу, временный сетевой сбой сам по себе канал не удаляет.
- `tools/check-public-release.py`: отсутствие учётных данных в URL, минимум 20 каналов 18+, категория 18+ первой, только русские группы, без детских каналов и дублей, с измеренными метками качества не ниже 1080p.
- Полная сборка eMMC OTA, проверка структуры образов и подписи прежним ключом проекта.
- Архив чистой установки eMMC для Rockchip Loader со всеми регионами, `rkusb.py`, инструкцией и внешним SHA-256.
- `tools/analyze-release-logs.py`: подсчёт предупреждений и ошибок сборки; критические ошибки блокируют публикацию. Отчёт анализа прикладывается к Release.
- `tools/check-release-evidence.py`: проверка аппаратного протокола соответствующего тегу выпуска.
- Сетевой захват и разбор во время аппаратного sanity обязателен для каждого выпуска; не реже раза в месяц повторять анализ журналов и трафика. В публичный протокол записывать только очищенную сводку, не PCAP.
- `.github/workflows/monthly-security-audit.yml` запускается ежемесячно и вручную: проверяет свежесть очищенной device-аудит-сводки (31 день), полный тестовый набор и журнал тестов. Сам отчет обновляется после контролируемого захвата на приставке.

Тег `dev-v<версия>` запускает GitHub prerelease. Dev-путь не требует `security_review=pass`; текущие риски остаются видимыми в приложенном протоколе, но сам анализ безопасности, журналов и трафика обязателен. Dev-релиз также требует успешных автотестов и функциональных/стабильностных проверок: холодного старта, журналов, QR, сети, IPTV, торрента, графики и отключённого дискового swap. Обычный тег `v<версия>` требует устранить блокирующие риски и закрыть проверку безопасности.

## Проверки на приставке

До публикации заполнить `docs/release-qa/<версия>.json`. Проверить холодную загрузку от подачи питания (не более 10 секунд), журналы после загрузки, QR-ссылки служб TorrServer/VLC и отдельный запуск приложения службы на приставке, проводную и Wi-Fi сеть, воспроизведение IPTV и торрента, плавность видео и графическую нагрузку. Во время sanity снять и разобрать сетевой трафик; проверить незашифрованные запросы, неожиданные узлы и утечки. Для каждой QR-службы кнопка запуска на приставке должна запускать именно приложение этой службы, которое затем откроется по QR; не запускать посторонний файловый менеджер. Ссылку QR обрабатывает устройство сканирования. Проверить, что дисковый swap выключен. Стабильный выпуск требует также закрытой проверки безопасности и нулевого `untriaged_errors`; dev-выпуск может оставить известные риски, но не может пропустить сам анализ или выпускать неразобранные ошибки, влияющие на стабильность/функции.

Сборочный GitHub runner не имеет доступа к живой приставке, поэтому его успешная сборка не считается результатом аппаратных проверок. Все автоматические и аппаратные отчёты публикуются вместе с OTA и APK. Пример незаполненного протокола для текущего 0.4.0 показывает, что именно ещё требуется проверить. Сетевые адреса и необработанные журналы не прикладывать к публичному отчёту.
