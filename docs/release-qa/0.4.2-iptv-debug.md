# Диагностика IPTV для кандидата 0.4.2 — 2026-11-07

## Приставка и проверка

Целевая H96 Max, Android 12, системная версия 0.3.9. IPTV APK 0.4.2 собран с ключом проекта и установлен поверх предыдущей версии без очистки данных. Установка прошла, versionCode=4002/versionName=0.4.2; флаг `tvbox_iptv_debug=1` и файл пользовательского плейлиста сохранились. После обновления APK до 0.4.2 launcher возобновился, а VLC медиасессия остановилась. Затем на приставке снова открыта категория «Для взрослых» и выбран первый поток EPG 7742: VLC на переднем плане, медиасессия PLAYING, журнал подтверждает MPEG-TS, HEVC и AAC. Снимок видеоповерхности ранее был чёрным; текущая SurfaceFlinger latency-выборка не вернула времён кадров. Это не позволяет подтвердить изображение и плавность на физическом экране; нужен визуальный sanity.

## Результат диагностики

- Все 184 взрослых потока встроенного старого плейлиста отвечали HTTP 401 на самой приставке. Это отказ источника до декодирования.
- Из альтернативных источников собраны 92 взрослых варианта. Первый проход дал 92 HTTP 200, повторный — 70 HTTP 200 и 22 HTTP 404; источники нестабильны.
- Диагностический preflight при выборе канала делал второй запрос параллельно VLC и мог мешать запуску. Запрос удалён из playback-пути. После исправления VLC передал поток демультиплексору MPEG-TS, определил HEVC/AAC и перешёл в PLAYING.
- Контрольный обычный 1080p поток ранее открыл аппаратный MediaCodec. Проверка DRM выявила ошибку: Android UI/framebuffer — 1920×1080, но HDMI выбирал 3840×2160p30 по Auto/EDID. После установки документированного Rockchip тайминга 1080p60 и перезагрузки DRM показывает 1920×1080p60. Это устраняет несоответствие системного выхода требованиям проекта.
- Повторный полный скан взрослой категории с приставки после выявления единичного host-side ffprobe 404 завершился 76/76 HTTP 200, без ошибок и таймаутов. ffprobe с VLC User-Agent определил EPG 7741 как HEVC Main, yuv420p, 1920×1080, level 120; host FFmpeg декодировал 145 кадров за 5 секунд. 404 от ffprobe с другим User-Agent не считается доказательством недоступности потока. В списке кодеков Android присутствуют аппаратный `c2.rk.hevc.decoder` и программный HEVC decoder.
- На VLC выполнен обратимый A/B тест режимов «Ускорение декодирования» и «Отключено» против исходного «Полное ускорение». Для EPG 7741 decoder-open/video-output события не появились ни в одном режиме. Повтор после фактического переключения HDMI с 4K30 на 1080p60 также оставил VLC в PLAYING без видеоплоскости/декодера. Значит, HDMI Auto был отдельной конфигурационной ошибкой, но не единственной причиной чёрного IPTV; причина остаётся на пути HLS/HEVC/VLC. VLC-логи URL подавлены системными свойствами, app-level отладка оставляет EPG ID и статусы без адресов.
- Пользовательский плейлист на приставке: 2894 канала, 76 взрослых, без детских, минимум 1080p; полный проход подтвердил HTTP 200 для 76/76 взрослых потоков. SHA-256: `5ca44920f00324385198316bc69cf2d277eaebf78d00b79eac0bf0dc0df4d64e`.
- Генератор следующего образа применил список 76 EPG ID, ранее проверенных приставкой, повторно измерил качество и прошёл публичный валидатор: 1291 канал, 70 взрослых 1080p, без детских и дублей, все категории русские, качество от 1080p. `Cartoonito RO` исключён по названию, несмотря на ошибочную исходную категорию. Собран локальный eMMC кандидат 0.4.2 и подписанный OTA; плейлист и APK в system.img сверены с исходниками. Образ не установлен и не опубликован.

## Статус выпуска

Отладка включена и исправление передано в исходники 0.4.2. Полный OTA собран локально, подпись CMS и checksum проверены; OTA не устанавливался. Физическую картинку/плавность, причину отсутствия декодера у IPTV после исправления HDMI, полное IPTV sanity после установки образа, торрент, графику, загрузку, сетевой захват и анализ безопасности ещё нужно проверить. До этого dev/stable публикация запрещена; OTA, требующий очистки данных, не устанавливать без отдельного подтверждения пользователя. Сырые URL, журналы и PCAP в отчёт не включались.
