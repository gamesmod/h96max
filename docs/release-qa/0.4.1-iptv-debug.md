# IPTV-диагностика для следующего кандидата — 2026-11-07

## Среда и метод

На целевой приставке с установленной системой 0.3.9 обновлено только приложение IPTV диагностическим APK, без очистки данных. Отладка включена через `Settings.Global`. Приложение последовательно опрашивало каналы категории «Для взрослых» непосредственно из сети приставки с паузой 0,5 секунды. В журнал попадали только EPG ID, HTTP-код и тип содержимого; URL и тела ответов не сохранялись.

## Результаты

- Встроенный плейлист: 184 из 184 потоков категории вернули HTTP 401. Это подтверждает отказ источника до декодирования, а не только ошибку запуска VLC.
- В альтернативных записях 13 настроенных источников найдены 92 варианта взрослых каналов. Первый прогон на приставке дал 92 ответов HTTP 200; повторная проверка позже дала 70 ответов HTTP 200 и 22 ответа HTTP 404, что показывает быстрое устаревание ссылок.
- При ручной проверке одного альтернативного потока VLC получил HTTP 200, разобрал MPEG-TS и обнаружил видео HEVC и аудио AAC. Состояние медиасессии переходило в PLAYING. Снимок экрана ADB оставался статичным; пользователь не наблюдал экран во время прогона, поэтому видимый кадр и плавность не подтверждены.
- Текущий релизный генератор заново проверил все настроенные источники и создал встроенный кандидат из 885 каналов: 95 взрослых, 91×1080p и 4×4K, детских нет. Публичный валидатор подтвердил категории, отсутствие дублей/детских каналов, качество от 1080p и отсутствие credentials в URL.
- По просьбе пользователя установлен полный пользовательский плейлист: 2912 каналов, 94 взрослых, детских нет, минимальное качество 1080p. SHA-256: `4fa82050759cf9733457e2f4a8d7b772d966c79345d8a8ad4f978d19c5efe512`. Проверочный скан на приставке подтвердил HTTP 200 для 93 из 94 взрослых потоков; последняя запись осталась без результата, когда приставка перешла в VLC. Полный проход на устройстве не подтверждён.
- Повторная проверка на приставке 2026-11-07 подтвердила, что override загружен: 2912 каналов и 58 категорий, категория 18+ первая, детских категорий нет. Два проверенных новостных потока (100% News UA и BBC One UK) вернули HTTP 401 и не дошли до декодирования. Поэтому чёрный кадр в этих попытках не указывает на отсутствующий видеокодек.
- В реестре Android на устройстве есть аппаратные декодеры H.264, HEVC, VP9, VP8, MPEG-2, MPEG-4 Part 2 и H.263; программный реестр дополнительно содержит AV1 и аудиоформаты AAC, MP3, Vorbis, Opus и FLAC. VLC установлен, версия 3.7.2. Отдельный codec pack не нужен для встроенных в VLC форматов.
- Проверка выполнена на Android 12 / выпуске 0.3.9. Отладочный флаг оставлен включённым; пользовательский override явно включён. Для этой сессии сохранены только сводные результаты без URL; сырые строки VLC с адресами источников не публиковались.

## Вывод и статус выпуска

Причина исходного отказа подтверждена: все 184 старых взрослых потока вернули HTTP 401 на приставке. В IPTV-приложении исправлен выбор M3U: встроенный плейлист используется по умолчанию, а внешний override включается явным переключателем. Диагностический сканер получил жёсткий 8-секундный общий лимит, включая DNS; при таймауте он прекращает пакетный прогон вместо зависания. CI повторно проверяет источники и включает в следующий кандидат только потоки с измеренным разрешением не ниже 1080p; текущая генерация и её валидатор прошли.

`iptv_playback` остаётся `pending`: видимое видео и отсутствие пропусков кадров не подтверждены, полный OTA следующего кандидата не установлен. Этот прогон не является полным release sanity или анализом сетевого трафика. Сырой PCAP не сохранялся.
